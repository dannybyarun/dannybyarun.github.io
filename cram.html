1. SE — Software Engineering (10 Dec)

Papers used: 8 — 2082, Model Set II, 2081, 2080, Model I, 2079, 2077, 2076.

What recurs

  1. COCOMO cost estimation. Effort grows faster than size because communication, coordination and rework grow with the number of people, not with the code. Exponents: 1.05 organic, 1.12 semi-detached, 1.20 embedded, so doubling size more than doubles effort; duration rises only as effort raised to a fraction, so a late large project cannot be rescued by schedule. (2082 Q2; 2081 Q1; 2080 Q12; Model I Q8; Model Set II Q5; 2079 Q12; 2077 Q9) — also sure.js se.10 gate answer. This is the single most repeated SE topic.
  2. Software configuration management (SCM). Activities: identification, version control, change control, status reporting, release. Chain: change request → impact analysis → CCB → implement → test → new baseline. (2080 Q1; Model I Q1; 2079 Q3; 2077 Q1; 2082 Q10) — sure.js se.10 top answer.
  3. Verification vs validation + inspection. Verification = "are we building the product right?" (static: reviews, inspections, walkthroughs). Validation = "are we building the right product?" (dynamic: testing, acceptance, beta). Inspection steps: planning, overview, preparation, meeting, rework, follow-up; roles: moderator, author, 3–4 inspectors, recorder. (2082 Q1; 2081 Q6; 2079 Q10; 2077 Q3; Model I Q7) — sure.js se.8 top answer.
  4. Structural vs behavioural models. Structural = static organisation (class, component, deployment). Behavioural = run-time states, events, transitions (state machine, activity, sequence). Behavioural matters because it exposes unhandled events, dead states, timing and concurrency errors. (2081 Q9; 2080 Q11; 2079 Q7; Model I Q12) — sure.js se.5 top answer.
  5. Prototyping: evolutionary vs throw-away. Evolutionary is engineered and becomes the product; throw-away answers one question and is discarded. (2079 Q1; 2080 Q5; 2076 Q5; 2077 Q2) — sure.js se.2 top answer.
  6. Plan-driven vs agile. Plan-driven signs off phases and delivers once; agile ships prioritised slices and absorbs change. Know the agile principles and agile project management. (2082 Q5; 2080 Q6; 2081 Q11; 2079 Q4) — sure.js se.3 top answer.
  7. Architectural patterns. MVC, client-server, pipe-and-filter, plus layered and repository views. Each buys one quality at the price of another: layering buys substitutability and adds latency; repository buys shared data and creates a bottleneck; client-server centralises control and creates one point of failure. (2080 Q3 asks layered, repository and pipe-and-filter; Model Set II Q2 asks the patterns; 2081 Q8 and 2076 Q7 ask architecture generally) — sure.js se.6 top answer.
  8. Requirements engineering + SRS. Four activities: elicitation, analysis and negotiation, specification, validation; plus requirements management. Good SRS: complete, consistent, unambiguous, verifiable, traceable, feasible, prioritised, uniquely identified. (2080 Q2; 2082 Q11; 2081 Q10; 2077 Q5; 2077 Q8) — sure.js se.4 top answer.

Numbers to memorise

COCOMO (formulas are printed in the paper, Model Set II Q5):

  • Organic: Effort = 2.4 × KLOC^1.05, Time = 2.5 × Effort^0.38
  • Embedded: Effort = 3.6 × KLOC^1.20, Time = 2.5 × Effort^0.32

Worked, from those formulas:

  • 320 KLOC organic → ≈ 1024.8 PM, ≈ 34.8 months (Model Set II Q5).
  • 320 KLOC embedded → ≈ 3651.6 PM, ≈ 34.5 months (Model Set II Q5).
  • 400 KLOC organic → ≈ 1295.3 PM, ≈ 38.1 months (2079 Q12).

2079 Q12 also asks for semi-detached at 400 KLOC, but this repo records only its exponent (1.12, sure.js se.10), not its coefficients. Do not invent them — check your class note for the two numbers.

Also memorise the two inspection numbers: 6 steps, 4 roles (sure.js se.8).

If you only have one hour

Write COCOMO twice — 320 KLOC organic + embedded, then 400 KLOC organic — then the SCM activity chain and the V&V/inspection six steps. Those three answers cover 2082 Q2/Q10, 2080 Q1/Q12, 2081 Q6, 2079 Q3/Q10.

2. CDC — Compiler Design and Construction (13 Dec)

Papers used: 8 — 2082, Model Set II, Model Set I, 2081, 2080, 2078, 2076, 2075.

What recurs

  1. SLR parsing table. Augment S' → S, build LR(0) item sets with closure and goto, compute FOLLOW, fill ACTION/GOTO, then check for conflicts. Reduce-reduce example: S → aAd | bBd | aBe | bAe, A → c, B → c; after reading c the state holds A → c. and B → c., and SLR puts both reduces in the d and e columns. (2081 Q1; 2075 Q4; 2076 Q4; 2080 Q10) — data/repeats.js r0, 4 papers. sure.js cdc.2 works the full table for E → (L) | a, L → L, E | E.
  2. FIRST and FOLLOW. Asked with a fresh grammar almost every year: (2082 Q11; 2081 Q6; 2080 Q12; Model Set I Q6; 2075 Q3). Use the worked check from sure.js cdc.2: for E → (L) | a, L → L, E | E, FOLLOW(E) = { ) , comma, $ } and FOLLOW(L) = { ) , comma }.
  3. Syntax-directed definition + annotated parse tree. Synthesized = value from children (one post-order pass). Inherited = value from parent or left sibling (L-attributed → one left-to-right pass). Worked value: (5*3+2)*5 = 85. (2075 Q5; 2076 Q5; 2082 Q3; 2080 Q8; 2078 Q8) — sure.js cdc.3.
  4. Three-address code, quadruples, triples, backpatching. Backpatching emits a jump with an empty target and keeps its index in a truelist/falselist; makelist, merge, backpatch fill the target later. (2082 Q7; 2081 Q2; Model Set I Q2; 2078 Q9; 2075 Q7) — sure.js cdc.7 has a fully numbered while example with its quadruples.
  5. Activation record + caller/callee duties. Record order: actual parameters, return value, control link, access link, saved machine status, locals, temporaries. (Model Set II Q9; 2081 Q5; 2075 Q9; 2078 Q10) — sure.js cdc.6.
  6. Code optimization. Three conditions: preserve observable behaviour, be profitable, do not change error reporting. Loop techniques: invariant code motion, strength reduction, induction-variable elimination, unrolling, jamming/fusion. (2082 Q2; 2080 Q4; 2076 Q8; 2075 Q8; Model Set I Q10) — sure.js cdc.9.
  7. Symbol table. One record per identifier: name, type, kind, scope, offset, size, declaration line. Linear list O(n); hash O(1) average; BST O(log n). (2082 Q6; Model Set II Q8; 2078 Q5; 2081 Q5) — sure.js cdc.5.
  8. Type checking. Static vs dynamic, then an SDD with .type set to a type or type_error; a type_error propagates upward so the statement is reported. (2075 Q6; 2076 Q6; 2078 Q3; 2082 Q12) — sure.js cdc.4.

Numbers and derivations to memorise

  • SLR steps: augment → LR(0) items (closure/goto) → FOLLOW → ACTION/GOTO → conflict check. Five named steps is enough for the method mark.
  • Hash example h(x) = (sum of ASCII) mod 7 for {sum, count, avg, total, temp} → buckets sum=5, count=0, avg=3, total=2, temp=4, no collisions (sure.js cdc.5, Model Set II Q8).
  • Annotated tree total = 85 for (5*3+2)*5 (sure.js cdc.3).
  • Backpatch lists: after a<b, truelist={100}, falselist={101} (sure.js cdc.7).

If you only have one hour

Do the SLR table from sure.js cdc.2 once by hand, then FIRST/FOLLOW on the 2080 Q12 grammar and one annotated tree. SLR alone appears in 4 of the 8 papers (data/repeats.js), and the table method is reused by every LR question.

3. EGOV — E-Governance (16 Dec)

Papers used: 7 — 2082, Model Set, 2081, 2080, 2079, 2078, 2076.

What recurs

  1. The five e-governance models. Broadcasting/wider dissemination (one-way push to everyone), comparative analysis (same data reused as a ranking), critical flow (push aimed at auditors and press), mobilization and lobbying (citizens push back), interactive service (a transaction the back office records). (2078 Q2; 2079 Q2; 2080 Q3; 2081 Q2; 2082 Q2; 2076 Q4; 2076 Q8; Model Set Q3) — sure.js egov.2 gate answer. Most repeated EGOV topic.
  2. Maturity model, five levels. Emerging (static information), Enhanced (searchable, downloadable), Interactive (two-way forms, enquiry), Transactional (full service + payment), Connected (single window across departments). (2082 Q3; 2080 Q6; 2079 Q6; 2078 Q6; 2076 Q2; Model Set Q5) — sure.js egov.2 top answer. data/repeats.js r1 counts 3 papers for the exact wording.
  3. E-readiness and infrastructure preparedness. E-readiness = how prepared a country is to deliver services electronically, measured across infrastructure, affordability, human skills, business environment, legal framework and government adoption. Data-system preparedness = core registries, standards, data quality, storage/integration, security/privacy, open data. (2082 Q10; 2080 Q7; 2079 Q8; 2078 Q8; 2076 Q5; Model Set Q6) — sure.js egov.3.
  4. E-government security. Stack the layers: physical, network, host, application, data, identity, audit, people; each assumes the layer above has failed. Management cycle: governance/policy, risk assessment, controls, monitoring and incident response, audit, awareness, continuous improvement. (2082 Q7; 2081 Q9; 2080 Q10; 2079 Q9; 2078 Q9; Model Set Q7) — sure.js egov.4.
  5. Data warehousing and mining. Warehouse is subject-oriented, integrated, time-variant, non-volatile; path is source → ETL → staging → warehouse → marts → OLAP/mining → dashboards. Uses: census projections, district clustering, price-spike detection, buffer-stock decisions. (2082 Q5; 2080 Q2; 2081 Q10; 2079 Q10; 2078 Q10; 2076 Q3) — sure.js egov.5.
  6. E-government vs e-governance. E-government is ICT at the delivery edge; e-governance covers the whole loop including the decision rule and feedback, so e-government is a subset. (2080 Q1; 2076 Q1) — sure.js egov.1 gate.
  7. E-government life cycle. The repo's ladder is information → interaction → transaction → transformation (sure.js egov.1). Papers ask it as a long answer (2079 Q5; Model Set Q1) and as a short note (2082 Q12). The repo does not spell out each stage, so pair the ladder with the five maturity levels above.
  8. Good governance through e-governance / SMART government. Asked five times (2082 Q9; 2079 Q4; 2079 Q7; 2078 Q7; 2081 Q7), but no sure.js unit gives a worked answer; build it from the five models and the maturity levels.

Numbers to memorise

  • 5 maturity levels — Emerging, Enhanced, Interactive, Transactional, Connected.
  • 5 models — Broadcasting, Comparative Analysis, Critical Flow, Mobilization-Lobbying, Interactive Service.
  • 4 warehouse properties — subject-oriented, integrated, time-variant, non-volatile.
  • 6 e-readiness components — infrastructure, affordability, human skills, business environment, legal framework, government adoption.
  • 8 security layers — physical, network, host, application, data, identity, audit, people.

If you only have one hour

Memorise the five maturity levels with one example each, then the five models with one line each. Those two lists are the backbone of 6 papers and 8 questions respectively (the models appear twice in 2076); add the four warehouse properties and you can answer every "explain the model" question.

4. NCC — .NET Centric Computing (20 Dec)

Papers used: 7 — 2082, Model Set, 2081, 2080, 2079, 2078, 2076. The 2076 paper is ASP-classic (ASP vs IIS, request/session object, ASP file access), not ASP.NET Core. Treat it as background only; the marks are in the Core papers.

What recurs

  1. State management. HTTP is stateless, so state is carried by the client (query string, hidden field, cookie, localStorage, JWT) or held on the server under an id (Session, TempData, ViewData/ViewBag, Cache, HttpContext.Items). TempData survives one redirect and is read once; ViewData lasts one request; Cache is application-wide. Cookies: 4 KB max, set HttpOnly, Secure, SameSite. Ten questions in the Core papers touch it: (2082 Q7; 2082 Q10; Model Set Q9; Model Set Q10; 2081 Q6; 2080 Q1; 2080 Q2; 2079 Q2; 2078 Q3; 2078 Q9) — sure.js ncc.6. Most repeated NCC topic. (2076 Q3 asks about session objects too, but that paper is ASP-classic.)
  2. .NET compilation and execution. C# → Roslyn → MSIL + metadata in an assembly → CLR verifies, JIT-compiles to native, caches. CLI = CTS + CLS + VES. (Model Set Q3; 2082 Q5; 2078 Q5) — sure.js ncc.2.
  3. SQL injection. String concatenation plus ' OR '1'='1 returns every row; the fix is a parameterised SqlCommand with @n, so input is data and never syntax. (2080 Q7; 2079 Q5; 2078 Q2; 2078 Q10) — sure.js ncc.9.
  4. XSS, CSRF, open redirect. The repo lists all three as vulnerabilities. XSS defence: Razor output encoding, never Html.Raw on user data, HttpOnly cookies, CSP. (2082 Q9; 2079 Q2; 2080 Q12; 2081 Q11; 2078 Q4) — sure.js ncc.8. The CSRF token and open-redirect fixes are not worked in the repo; see the note below.
  5. ADO.NET and EF Core. ADO.NET: Connection opens, Command carries SQL and parameters, Reader streams forward-only, Adapter fills a DataSet. EF Core: DbSet is a table, LINQ is the request, DbContext tracks entities and SaveChanges writes only differences. (2082 Q3; 2081 Q3; Model Set Q8; 2080 Q1; 2078 Q3) — sure.js ncc.5.
  6. Hosting and deployment. Kestrel owns the socket; IIS (in-process via ANCM or out-of-process reverse proxy), Nginx, Docker. Deploy steps: dotnet new → restore → build → run → test → publish -c Release → copy + hosting bundle / Nginx / Docker → set ASPNETCORE_ENVIRONMENT → migrations → HTTPS → smoke test. (2081 Q4; 2080 Q3; 2079 Q3; 2078 Q2; Model Set Q3; Model Set Q13) — sure.js ncc.9.
  7. MVC, action results, routing, model binding. Routing maps URL to action; model binding fills parameters; data annotations set ModelState. Results: View, Json, Content, File, RedirectToAction, Ok, NotFound, BadRequest, NoContent, Challenge. A successful POST returns RedirectToAction, not View, so refresh does not repeat the insert. (Model Set Q2; 2081 Q2; 2080 Q4; 2080 Q5; 2080 Q6; 2079 Q9) — sure.js ncc.4.
  8. Lambda and async/await. Expression lambda returns one expression; statement lambda is a block with return. await becomes a state machine that frees the request thread. (2082 Q1; Model Set Q5; 2080 Q12; 2079 Q12) — sure.js ncc.1. Delegates and events are asked in 2079 Q12 but not worked in this unit; learn their syntax from your class note.

Numbers to memorise

  • Deploy sequence: 7 steps (sure.js ncc.9).
  • Status codes used in the answers: 302 redirect after POST, 201 created, 204 no content, 401 challenge (sure.js ncc.4, ncc.8).
  • Cookie size 4 KB (sure.js ncc.8).
  • CLI = CTS + CLS + VES (sure.js ncc.2).

Not in the repo: the three DI lifetimes (2081 Q9 asks for the container life cycle), the CSRF anti-forgery token, Url.IsLocalUrl for open redirects, and Razor's exact rendering pipeline. Learn those from your class note.

If you only have one hour

Draw the state-management table — client vs server, and TempData vs ViewData vs Session vs Cache — then write the parameterised-SQL fix and the 7-step deploy sequence. Those three cover 2082 Q7/Q10, 2080 Q2/Q7, 2079 Q3/Q5/Q9, 2078 Q2/Q9.

5. TW — Technical Writing (23 Dec)

Papers used: 8 — 2082, Model Set I, 2081, 2080, 2079, 2078, 2075, 2074. This subject is task-heavy: most marks come from *writing* a memo, letter, news release or resume, not from recalling a definition. 2074 is a six-question paper mixing tasks with grammar (Q1), and 2075 mixes tasks with grammar (Q5) and one definition question (Q6), so the definition marks come from 2078–2082 and the model set. The facts below are the scaffolding; the practice is the answer.

What recurs

  1. What technical writing is. Writing that changes what a specific reader can do, so the test is behavioural, not aesthetic. Characteristics: clarity, accuracy, organisation; creative writing is judged by feeling, technical writing by whether the task gets done. (2082 Q4; Model Set Q5; 2081 Q9; 2080 Q5; 2078 Q1) — sure.js tw.1.
  2. Audience analysis. Primary reader acts on it; secondary approves or passes it on; tertiary meets it by accident. Knowledge, role, attitude and reading situation set vocabulary, depth, order and medium. Build the profile for the mobile-banking manual: primary = account holders, secondary = branch and support staff, tertiary = auditors and regulators. (2082 Q1; 2081 Q1; Model Set Q6) — sure.js tw.2.
  3. The writing process. Planning → drafting → revising → copyediting → publishing. It loops, and revision must come before copyediting: polishing a section that should be cut is wasted work. (2082 Q2; 2080 Q2; 2081 Q11; Model Set Q2) — sure.js tw.3.
  4. Brief correspondence. Memo = internal, so only TO / FROM / DATE / SUBJECT and no salutation or close. Letter = may leave the organisation, so it needs inside address, salutation, body, complimentary close and signature. (2082 Q9; 2080 Q14; 2079 Q15; 2078 Q6; 2078 Q8; 2074 Q5) — sure.js tw.4.
  5. Document design and graphics. Four principles: proximity, alignment, repetition, contrast. Every graphic needs title, axis labels with units, legend and source so it can be read alone and cannot exaggerate by a truncated axis. (2082 Q3; 2082 Q8; Model Set Q12; 2080 Q4; 2075 Q4) — sure.js tw.5.
  6. Report structure, and information vs recommendation. Front matter (title page, transmittal letter, contents, list of figures, executive summary), body (introduction, findings, conclusions, recommendations), back matter (references, appendices, glossary, index). An information report presents findings; the moment it says "we recommend" it has become a recommendation report. (2081 Q3; Model Set Q1; 2079 Q12) — sure.js tw.7.
  7. Resumes: chronological vs functional. A resume is an argument for one advertised job, not a career record; it selects evidence and quantifies results. (Model Set Q9; 2081 Q10; 2080 Q9; 2078 Q11) — sure.js tw.8.
  8. Ethics. Accuracy is a property of each sentence; honesty is a property of the whole document. Dilemmas: undocumented data-loss bug, pressured benchmark deletion, breach described as minor, copied text. Seven steps: name it, gather facts, identify stakeholders, check code/contract/law, escalate in writing, refuse to sign, review. (2082 Q6; 2081 Q4; Model Set Q4; Model Set Q13; 2080 Q6; 2080 Q15) — sure.js tw.12.

Numbers to memorise

  • 5 writing stages — planning, drafting, revising, copyediting, publishing.
  • 4 memo header fields — TO, FROM, DATE, SUBJECT.
  • 5 flowchart symbols — oval start/stop, rectangle process, diamond decision, parallelogram input/output, arrow flow (sure.js tw.5).
  • Report front matter has 5 named parts (sure.js tw.7).
  • Gantt example in the paper: 12 weeks = 2 requirements + 2 UI/UX + 5 development + 2 testing + 1 deployment (Model Set I Q7).

If you only have one hour

Learn the 5-stage process, the memo header, and information-vs-recommendation. Then hand-write one memo and one news release with the inverted pyramid — the paper asks you to produce a document every single year (2082 Q7/Q9; 2080 Q7/Q14; 2079 Q9/Q15).

6. ECOM — E-Commerce (27 Dec)

Papers used: 6 — 2082, 2081, 2080, 2079, 2078, 2076. This is the thinnest set: 6 papers, and a few questions have no worked answer in data/sure.js (flagged below). Do not pad — answer from the definitions here.

What recurs

  1. Security chain. Six properties: confidentiality, integrity, availability, authenticity, non-repudiation, privacy. A hash proves integrity but not authorship, because anyone can compute it; only encrypting the digest with the sender's private key, verified through a certificate, adds authenticity and non-repudiation. Digital signature = hash encrypted with sender's private key. (2082 Q3; 2082 Q8; 2081 Q1; 2081 Q8; 2080 Q8; 2079 Q2; 2078 Q2; 2076 Q8) — sure.js ecom.5. Most repeated ECOM topic.
  2. Electronic payment + SET. Chain: cardholder, merchant, gateway, acquiring bank, association, issuing bank. Dual signature: hash OI and PI, hash the two digests together, encrypt with the cardholder's private key; merchant gets OI + H(PI) + DS, gateway gets PI + H(OI) + DS, so neither reads both halves. (2082 Q2; 2081 Q6; 2080 Q2; 2079 Q3; 2078 Q3) — sure.js ecom.3.
  3. Business models. Eight elements: value proposition, revenue model, market, rivals, advantage, strategy, organisation and team. B2B forms: e-distributor, e-procurement, exchange, industry consortium, private industrial network. (2081 Q3; 2079 Q1; 2078 Q1; 2080 Q1) — sure.js ecom.2.
  4. SEO. Asked four times (2082 Q11; 2081 Q11; 2079 Q10; 2078 Q11), but data/sure.js has no SEO unit: ecom.4 only lists SEO as a growth item. Do not invent PageRank mechanics; answer from your class note.
  5. Recommendation: content-based vs collaborative filtering. Collaborative needs a user-item matrix, so it fails a new visitor or a new item; content-based compares item attributes with what the visitor already viewed, so it works before any community history exists. Hybrids fall back to popularity until history accumulates. (2082 Q12; 2080 Q11; 2078 Q12) — sure.js ecom.7.
  6. Marketing metrics. CTR = clicks ÷ delivered × 100, bounce-back rate = bounced ÷ sent × 100, conversion rate = orders ÷ clicks × 100. CTR is a message problem, bounce a list problem, conversion a page problem. (2081 Q2 asks all three; 2079 Q9 asks CTR among impressions/page views). 2082 Q9/Q10 and 2080 Q3 ask other display-ad metrics (CPM, reach, view-to-cart), not these three. — sure.js ecom.6.
  7. Electronic Transaction Act of Nepal, 2063. Gives electronic records, contracts and signatures legal standing; licenses certifying authorities; punishes unauthorised access, fraud, piracy and privacy violation; creates an Information Technology Tribunal. (2082 Q4; 2081 Q12; 2080 Q12) — sure.js ecom.1.
  8. Catalogs. sure.js ecom.4 covers catalogue content (product data, photographs, search-friendly descriptions, category tree, internal search), but not the static-vs-dynamic distinction the papers ask for (2080 Q7; 2078 Q7; 2079 Q6). Answer that half from your class note.
