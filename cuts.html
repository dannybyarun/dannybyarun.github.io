SE · se.10 Software Management 10 marks · 161 words

In the software development process, how does software configuration management facilitate the changes that may occur during different stages of a software development life cycle? Justify your explanation with example.

Software configuration management (SCM) identifies, controls and tracks every item that makes up a product — code, documents, test data, build scripts — so change is deliberate, traceable and reversible.

Activities — identification, version control, change control, status reporting and release — run in every phase: Requirements: each requirement and SRS draft is a versioned configuration item; changes pass through a change request and the change control board (CCB).

Design: UML models are baselined; a design change is impact-analysed through a traceability matrix before approval.

Implementation: work is done on Git branches, so two programmers cannot silently overwrite each other.

Testing: test cases are versioned with the code, so a failure is reproducible against the exact build.

Release and maintenance: numbered baselines allow rollback and trace a defect to the shipped version.

Example: the bus fare changes — a request is raised, the CCB approves, requirement, design and tests are updated together and released as v2.1 while v2.0 stays for rollback.

SE · se.8 Software Testing 5 marks · 80 words

Difference between verification and validation. Explain software inspection process.

Verification asks 'are we building the product right?' — it confirms that a work product conforms to its specification.

It is static: reviews, inspections, walkthroughs.

Validation asks 'are we building the right product?' — it confirms that the system meets the user's real need.

It is dynamic: testing with real data, acceptance and beta testing.

So verification compares the artefact with the specification, while validation compares the product with the need; a system can be verified against a wrong specification.

Prototyping helps because a prototype is built early, shown to users and refined, so it (1) clarifies vague or conflicting requirements that interviews miss; (2) checks feasibility of technology or interface before heavy investment; (3) improves communication — users react to a working screen far better than to a document; (4) cuts requirement risk and rework by finding errors while change is cheap; (5) supports incremental delivery where an evolutionary prototype grows into the product.

Backpatching: generating code in a single pass while jump targets are still unknown.

A jump is emitted with an empty target field and its instruction number is collected in a list (truelist or falselist); when the target label becomes known, the list is patched.

CDC · cdc.1 Introduction to Compiler 10 marks · 124 words

Difference between compiler and interpreter. “Symbol table is necessary component of compiler”. Justify this statement with examples.

Translation: a compiler translates the whole program into object code before running it; an interpreter executes the source statement by statement.

Output: the compiler produces an object or executable file; the interpreter produces only results, no file.

Speed: compiled code runs faster because decoding happens once; interpretation is slower.

Errors: the compiler scans everything and reports all errors together; the interpreter stops at the first error.

Memory: the compiler needs space for the object code and is itself larger; the interpreter needs less.

Examples: C, C++, Go are compiled; Python, JavaScript, Ruby are interpreted.

Java uses both (javac then the JVM).

Symbol table is a necessary component — every phase uses it: Lexical analysis inserts each identifier as it is recognised, with its lexeme.

CDC · cdc.8 Code Generation 10 marks · 118 words

Discuss about the different factors affecting target code generation.

Factors affecting target code generation: Target machine instruction set: which operations exist.

With no multiply instruction the generator must emit shifts and adds; register-to-register and register-to-memory machines need different sequences.

Number and types of registers: more registers mean fewer loads, stores and spills, and floating-point registers change how reals are moved.

Addressing modes: indexed, indirect and auto-increment modes let x = y[i] become one instruction instead of separate address arithmetic.

Instruction cost and timing: the generator must pick the cheapest correct sequence, not the most obvious one, and must respect delayed branches and pipeline stalls.

IR form and quality: three-address code organised into basic blocks with good temporaries produces better code than a raw tree with redundant temporaries.

Explain the complete technical writing process from planning to publishing. How does collaborative writing enhance or complicate this process? Discuss the advantages, challenges, and conflict resolution strategies in collaborative writing. Support your answer with examples from software documentation or IT project scenarios.

Planning, drafting, revising, copyediting, publishing.

Collaboration changes how each stage runs, not the stages themselves.

Planning: one writer fixes purpose, audience and outline; sections and deadlines are assigned.

Drafting: parts are written in parallel by whoever is closest to the knowledge — a developer writes the API reference, a tester the known issues.

Revising: a comment-and-track-changes review cycle, where conflicts surface.

Copyediting: one editor applies a single style sheet so the document reads in one voice.

Publishing: one owner controls the final version and the archive.

Conflict resolution: agree outline and style guide before writing; give one editor final say on language; settle disputes by evidence and reader need, not seniority; escalate to the document owner with a deadline; log every decision in the shared file.

Example: a manual by four authors fails when each names the same button differently — the style sheet is the fix.

Describe the structure and key components of a technical report. How does this structure enhance the report’s effectiveness?

A technical report has a fixed architecture because readers do not read it front to back; they hunt for a section.

Front matter: title page, letter of transmittal, table of contents, list of figures and an executive summary, which alone lets a manager decide in two minutes.

Introduction — background, problem, purpose, scope, limitations, method.

Findings — evidence under headings, with tables and figures.

Conclusions — what the evidence shows, with no new material.

Recommendations — specific, actionable, prioritised and costed.

Back matter: references, appendices for raw data and questionnaires, glossary and index.

Why it works: a predictable location saves search time; the summary and recommendations serve decision-makers; appendices keep detail available without bloating the body; references make claims checkable; headings allow selective reading; and a stated limitation builds credibility.

ECOM · ecom.3 Electronic Payment System 10 marks · 124 words

What is a dual signature? Describe the dual signature operations? How is dual signature used during purchase request operation of SET protocol?

A dual signature lets a cardholder sign order information (OI) and payment information (PI) so that the merchant sees only OI and the bank only PI, yet both can prove they belong to the same purchase.

Compute H(OI) and H(PI).

Concatenate and hash again: H(H(OI) || H(PI)).

Encrypt with the cardholder's private key — the dual signature DS.

Send the merchant OI, H(PI), DS; send the gateway PI, H(OI), DS.

Merchant hashes OI, joins it with H(PI), decrypts DS with the public key and compares; the gateway does the mirror check.

Each party verifies using its own half plus the digest of the half it never sees, so neither reads the other's data, but a mismatch proves tampering.

This gives confidentiality, integrity and non-repudiation.

ECOM · ecom.5 Security in E-Commerce 10 marks · 121 words

How are digital signatures used in e-commerce security? How often are social engineering attacks vulnerable to e-commerce? Being an e-commerce security expert, how can you combat social engineering attacks?

A digital signature is the hash of a message encrypted with the sender's private key.

The receiver re-hashes the message and decrypts the signature with the sender's public-key certificate; a match proves the message is unaltered and came from the key holder.

Uses in e-commerce: authenticating buyers and merchants, protecting order and payment messages, giving non-repudiation, securing SET's dual signature, and satisfying the Electronic Transactions Act 2063, which gives digital signatures legal validity.

Social engineering is highly effective against e-commerce because staff handle many low-value contacts, trust a familiar brand voice, and hold refund, KYC and admin powers worth money.

Attacks: phishing, pretexting as eSewa support, fake courier calls, baiting, tailgating.

Awareness training with simulated phishing and a no-blame reporting rule.
